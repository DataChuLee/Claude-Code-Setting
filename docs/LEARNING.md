# LEARNING.md — 실패 패턴과 환류

HARNESS.md는 사건 기록이다. 이 문서는 그 사건들을 **패턴**으로 묶고, 반복되는 패턴을 어떤 장치로 막았는지 적는다.

## 환류 절차
1. **기록**: 실패가 나면 HARNESS.md의 해당 Phase "실패와 해결"에 사실을 적는다. 증상, 원인, 해결을 쓴다.
2. **분류**: 아래 표에서 같은 패턴을 찾아 발생 칸에 추가한다. 맞는 패턴이 없으면 새 줄을 만든다.
3. **두 번째 발생부터 강제 장치로 바꾼다.** 교훈 문장만 남기고 끝내지 않는다. 강제할 수 있는 가장 강한 수단을 고른다.
   - 강한 것부터: **테스트** > **훅·guard** > **워크플로 단계** > CLAUDE.md·스킬 문장
   - 테스트는 먼저 실패하는 것을 확인한다. 고치기 전 코드에서 빨간불이 나야 장치가 실제로 그 실패를 잡는다는 증거가 된다.
4. **연결**: 대응 칸에 테스트 이름이나 파일을 적는다. 상태 칸은 `강제됨`, `부분`, `문장만`, `한계` 중 하나로 쓴다.
5. **관측**: Phase가 끝나거나 PR을 몇 개 올리면 숫자를 본다.
   - 로컬: `python .claude/hooks/observe.py`
   - CI: `gh run download <run-id> -n gate-log` → `python .claude/hooks/observe.py gate-log.jsonl`
   - 같은 검사가 반복해서 block되거나 리뷰 거절률이 오르면 그것도 패턴으로 2번부터 진행한다.
